# ufo2api

使用 Node.js 直接连接 UFO，不需要安装 UFO CLI。提供本地可视化控制台、账号切换、账号独立代理和 OpenAI 兼容接口。

## 启动

需要 Node.js 20.18.1 或更新版本：

```sh
git clone https://github.com/JamesZhaoY/ufo2api.git
cd ufo2api
npm install
npm start
```

打开 [http://127.0.0.1:8787/](http://127.0.0.1:8787/) 后，使用首次启动时生成的控制台密码登录；密码保存在 `.ufo/admin-password`（32 位，权限 600）。首次运行会自动导入旧版的登录凭据。要添加账号，点击「添加账号」，输入邮箱，收到验证码后在页面填写。账号列表支持搜索、按名称或可用额度排序及分页；额度未知的账号排在额度排序末尾。聊天请求由账号池策略选择工作区及出口；已经在运行的请求继续使用发起时的账号。

可为每个账号绑定 `http://host:port` 或 `https://host:port` 代理；如需认证，可以使用 `http://user:password@host:port`。登录、模型查询和对话请求均使用该账号的代理。SOCKS 代理当前不支持。代理地址及登录凭据保存在 `.ufo/accounts.json`，文件权限为 600；界面不显示代理密码或 UFO 凭据。

## Docker 部署

在项目目录中执行：

```sh
docker compose up -d --build
docker compose exec ufo cat /data/admin-password
```

访问 `http://127.0.0.1:8787/`，使用命令输出的 32 位密码登录。Docker 的 `ufo_data` 数据卷保存控制台密码、API Key、账号、代理设置和本地缓存；重新创建容器不会自动更换密码。不要执行 `docker compose down -v`，除非你明确要删除该卷和数据。Docker 默认启用网页通道和会话增量缓存、关闭摘要压缩；可通过 `UFO_TRANSPORT`、`UFO_WEB_SESSION_CACHE`、`UFO_CONTEXT_COMPACT` 环境变量覆盖。Docker 使用独立数据卷，不会自动带入本机账号；需要在页面重新登录或导入备份。

默认端口只绑定本机。若要通过 HTTPS 反向代理远程访问，设置 `UFO_PUBLIC_ORIGIN=https://你的域名` 并让代理保留原始 `Host`，然后重新创建容器；浏览器 Cookie 将启用 `Secure`。如果更改 `UFO_HOST_PORT`，也需要将 `UFO_PUBLIC_ORIGIN` 配置为浏览器访问的完整 origin。`UFO_BIND_ADDRESS` 可调整主机绑定地址；直接暴露 HTTP 会使密码和会话在网络中明文传输，应使用 HTTPS 反向代理。

本机直接运行时，可通过 `cat .ufo/admin-password` 查看密码。密码首次生成后保留不变，服务重启会让现有控制台会话失效。控制台密码与 OpenAI API Key 是两个独立凭据。

## 网页传输模式（推荐用于 DSH 长上下文）

PowerShell 启动：`$env:UFO_TRANSPORT='web'; npm start`。Docker 可在 environment 中设置 `UFO_TRANSPORT: web`。

网页模式使用工作区的 `chat` 助手：首次向 `/surface/web/agents/{id}/chat?conversation=new` 提交完整上下文，后续通过真实 conversation ID 追加新消息，从 `/surface/web/turns/{turn_id}/stream` 读取 SSE。它跳过本项目的上下文摘要和工具目录分页；即使设置 `UFO_CONTEXT_COMPACT=1`，网页模式也不执行摘要。请求取消或响应流异常时会尝试停止已创建的上游轮次，不自动重发消息。

网页模式默认启用增量会话。首次发送完整历史和工具定义；后续历史严格接续时只发送新增消息/工具结果，不重复发送系统指令与工具定义。工具结果回传时会同步上一轮工具调用的客户端 ID。修改已有历史、重复原请求、切换账号凭据/代理/模型或更改工具配置时，使用新会话发送完整上下文，避免串线。只有本地响应成功发送后才确认缓存；取消、上游失败、格式校验失败后不复用这次会话。每个会话请求串行处理。网页助手本身仍可能使用其工作区能力；提示词要求客户端工具由客户端执行，但这不是上游能力隔离保证。

默认仍保留 CLI 模式；设置 `UFO_TRANSPORT=cli` 可显式选择旧路径。网页路径未套用 CLI 的 39000 字节本地阈值，但仍受上游实际限制和本服务 32 MiB 请求体限制，不能认为上下文无限。工作区需有名为 `chat` 的助手。网页协议同样属于内部接口，可能变化。

## OpenAI 兼容接口

- Base URL：`http://127.0.0.1:8787/v1`
- `GET /v1/models`：返回当前账号保存在本地的模型列表，另外包含兼容旧配置的 `ufo` 别名。
- `GET /v1/models/{model}`：查询单个模型，带 `/` 的模型 ID 需要 URL 编码。
- `POST /v1/chat/completions`：`model` 使用返回的模型 ID；`ufo` 和 `auto` 均使用 UFO 自动模型选择。切换模型目录账号后，显示该账号保存的列表。

```sh
curl http://127.0.0.1:8787/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <你的 API Key>' \
  -d '{"model":"gpt-6-luna","messages":[{"role":"user","content":"你好"}]}'
```

`stream: true` 支持 SSE 流式输出。文本消息会拼接传给 UFO 助手，角色隔离和行为不等同于原生 OpenAI API；支持通过提示与结果解析适配函数工具调用和 `json_object`；工具由客户端执行。网页通道支持图片附件；暂不支持 JSON Schema 严格约束、多候选和精确 token 统计，采样参数不会传给 UFO。调用可能消耗 UFO 额度。

默认只监听本机，首次运行会随机生成 API Key，保存在 `.ufo/api-key`（权限 600）。在控制台「系统设置」查看、复制、修改或重新生成；所有 `/v1` 请求都必须携带 `Authorization: Bearer <API Key>`。设置 `UFO_PROXY_API_KEY` 环境变量时，该值优先并锁定页面修改。控制台使用独立的密码登录，不使用 API Key。`UFO_PROXY_HOST`、`UFO_PROXY_PORT`、`UFO_TIMEOUT`（秒）和 `UFO_HOME` 可调整绑定与配置位置。默认只接受本机控制台地址；远程访问需配置 `UFO_PUBLIC_ORIGIN` 和 HTTPS，服务自身不提供 TLS。

UFO 的内部接口并非公开稳定接口，协议变更可能导致模型查询或调用失效。请求关闭 UFO 公共互联网访问，但 UFO 助手仍可能使用工作区工具或请求授权。

测试：`npm test`。

### 截图和图片消息

`messages[].content` 可使用字符串或文本块数组（`{type:"text",text:"..."}`）。网页通道还支持 `image_url` 的 base64 data URL，以及 MCP `image`（`data`/`mimeType`）和 base64 `source` 图片块，可用于用户消息或工具截图结果。图片以网页端相同的 multipart `message`/`file` 方式上传，不会把 base64 塞入提示词或悄悄丢弃图片。

支持 PNG、JPEG、WebP、GIF；单张最多 10 MiB，单次请求最多 32 张、合计 20 MiB 图片，请求体总上限为 32 MiB。远程图片 URL 暂不下载；CLI 模式不支持图片。无效内容返回 400，并在 `error.param` 标明消息位置。图片识别能力仍取决于所选上游模型。

续聊命中缓存时只上传新增消息中的图片；切换会话或账号时重新上传所需历史图片。缓存只保留消息哈希，不保留图片字节。`web_context.attachments` 记录本次附件数量，输入字节数包含图片原始字节（不含 multipart 边界开销），日志不记录图片内容。

## 批量导入与导出

在「账号管理」勾选账号后点击「导出选中账号」，可只下载选中账号的 JSON 备份；「导出全部账号」仍可备份全部账号。选择本页仅影响当前搜索、筛选和分页所显示的账号，翻页后保留已选项，可通过「清空选择」取消；「导入账号」选择同格式的 JSON 文件。备份包含每个账号的邮箱/名称、UFO 登录凭据、工作区地址和代理地址（含代理密码）。**文件是明文，持有者可能访问相应账户；请只在可信设备间传递并妥善保管。**

示例格式：

```json
{
  "format": "ufo-accounts",
  "version": 1,
  "accounts": [
    {"name": "user@example.com", "token": "UFO 登录凭据", "workspace": "https://app.ufo.ai", "proxy": "http://127.0.0.1:7890"}
  ]
}
```

导入最多 500 个账号、文件不超过 2 MB。按不区分大小写的账号名称与工作区地址匹配：已有账号会跳过，不覆盖凭据或代理；其余账号合并添加。整个文件必须通过格式校验才会保存，导入不会改变已有当前账号。只有账号列表为空时，第一个导入的账号会成为当前账号。导入后会尝试一次加载模型和额度；凭据过期时需要重新登录。导入来源不可信的文件可能将请求和账号凭据发送到文件中指定的工作区或代理，请只导入可信备份。

## 账号池、额度与粘性对话

控制台的「系统设置」提供三种策略：

- **优先额度**：在已知余额且未到拒绝阈值的账号中，选择 `余额 − UFO 拒绝阈值` 最大的账号；无已知可用余额时才使用额度未知的账号。
- **随机负载**：从未确认耗尽的账号中随机选择。
- **轮询使用**：依次选择未确认耗尽的账号。默认策略为轮询。

账号余额来自 UFO 的工作区账单接口，显示的是余额及扣除拒绝阈值后的可用金额，不是 token 数。UFO 未设置支出限制时，不能据此认定额度无限；查询失败显示为未知，而非零。额度保存在本地，不因时间到期或普通调用而自动刷新；页面勾选账号后点击「刷新选中额度」只查询选中账号，或点击「刷新全部额度」重新查询全部账号。登录、导入或首次迁移现有账号时会加载一次。额度已达拒绝阈值的账号不会分配新请求。未知额度的账号仍可能被选择。上游明确返回额度不足时，接口会冻结该账号并解除其粘性绑定；本次请求返回错误，客户端下次重试按账号池策略选择其他可用且支持所选模型的账号。本次请求不会在服务端自动重发。

「模型目录账号」切换只控制页面和 `/v1/models` 显示的账号，聊天请求由账号池分配。指定模型时，仅在能够确认支持该模型的账号中选择。

粘性对话默认开启，有效期默认 60 分钟。推荐客户端对同一对话发送相同的 `X-Conversation-ID` 请求头；不同对话使用不同 ID。未提供时，系统根据开头的 system/developer 消息和首条 user 消息识别对话，因此相同开头的不同对话可能被识别为同一会话。粘性映射保存在进程内，超时或服务重启会清除；绑定账号额度耗尽时会解除绑定，下一次请求自动切换到其他可用且支持所选模型的账号；账号被删除或仍有额度但不支持所选模型时继续返回错误。CLI 模式仍每次创建上游会话；网页模式会在历史严格接续时复用会话，增量提交。客户端仍必须发送完整 OpenAI 消息历史，代理用它校验分支并在缓存未命中时恢复上下文。上游仍可能计费历史 token，不能把发送字节减少比例当作费用节省比例。

## 首页与最近调用

「首页概览」显示账号数量、已知可用总额度及最近调用状态。总额度按凭据中的工作区标识去重，并扣除 UFO 的拒绝阈值；无法查询、未设置支出限制或缺少额度数据的账号不会计入，页面会提示。若无法识别工作区，合计可能重复。

从本版本开始，服务最多在 `.ufo/activity.json` 保留最近 200 次聊天接口请求的时间、账号 ID、账号名称、模型、结果、HTTP 状态和耗时，权限为 600。不会保存请求或回复内容、验证码、会话 ID、密钥或代理地址；升级前的请求不会回填。页面的调用统计和列表仅基于这些本地记录，不代表 UFO 全部历史用量。用户中断的流式请求会标记为中断，服务端返回错误会标记失败。

## 工具调用兼容范围

支持 OpenAI Chat Completions 的 `tools`、`tool_choice`、`tool_calls`、`role: tool` 和旧版 `functions`/`function_call`，以及 `response_format: {"type":"json_object"}`。代理将工具定义和历史交给 UFO，并将其文本结果解析为标准 `tool_calls`；工具实际由客户端执行并提交结果。工具调用需等筛选与校验完成。工具筛选确认无需调用后可提前流式输出文本；最多三页的目录会等待所有页面确认，多于三页或格式不符合时回退到缓冲输出。小工具集也支持按工具状态提前输出文本。普通文本流仍实时输出。指定工具时只发送该工具的完整定义，减少无关上下文。普通及快路径工具结果均校验参数，缺少必填字段或类型不符时返回错误；校验器按 Schema 内容缓存，最多保留 128 项。当前校验使用 Ajv 默认 JSON Schema 方言及严格模式，不支持的 Schema 也会返回错误，不自动修复参数。上游不保证严格遵守函数 JSON Schema，也可能返回无法解析的内容；此时会返回错误，不会执行工具或伪造结果。流已开始后遇到上游错误会断开连接，不会发送成功结束标记。JSON Schema 结构化输出和多模态工具暂不支持。


DSH 等客户端提供大量工具时，代理会按 UFO 的单次输入大小限制分页发送工具名称，不在初选阶段发送无关工具的说明。它会在预算允许时提供与请求相关的少量完整定义，让模型在一次调用中选择工具并生成参数；参数通过 JSON Schema 校验才直接使用，否则回退到再次生成。最多选 8 个工具参与本轮调用。工具选择基于模型判断，不能保证一定选中正确工具，且分页可能增加延迟与用量。如果单独的对话历史已超过上游可接收的长度，默认返回 413；可缩短上下文，或显式启用下文的自动摘要。UFO 模型拒绝请求时，代理返回 422，避免客户端对拒绝结果反复重试。

最近调用记录还显示账号检查、工具筛选、上游生成和首字输出的耗时（旧记录没有这些分项）。模型和额度保存在 `.ufo/state-cache.json`（权限 600），正常聊天请求以及进程重启均使用本地数据；登录、导入或首次迁移旧账号时会加载一次，之后只能手动刷新。实际余额可能已经改变，额度优先策略也基于上次保存的值；如遇余额不足、账号变更或模型列表变化，请手动刷新。大工具目录的快路径在条件允许且参数通过校验时可省去一次生成；否则回退到原两阶段流程。

## Outlook 邮箱管理与 UFO 注册

控制台「邮箱管理」可粘贴或选择 UTF-8 TXT 文件，每行格式：

```text
邮箱----密码----Microsoft OAuth 客户端 ID----Microsoft OAuth 刷新令牌
```

最多一次导入 500 行。格式中的密码只在浏览器中解析，不会上传、保存或发给 Microsoft；刷新令牌会原样保存到服务端 `.ufo/mailboxes.json`（Docker 中为 `/data/mailboxes.json`，权限 600），包括末尾的 `$$`。默认跳过已有邮箱，可勾选替换授权。UUID 会作为 OAuth `client_id` 尝试使用；是否匹配取决于该刷新令牌原始授权，不能仅凭格式保证。邮箱文件和刷新令牌具有敏感访问权限，应妥善保护。

选择邮箱并点击「注册选中邮箱」，每批默认最多 50 个，可在「系统设置 → 注册与代理」调整为 1–500；邮箱列表支持按注册状态筛选以及选择每页 10、20、50 或 100 条。注册并发默认为 2，可在「系统设置」调整为 1–20。程序使用 Microsoft Graph 读取收件箱和垃圾邮件；授权不支持时尝试只读 Outlook IMAP。它会先记录旧邮件，再从「系统设置」中的代理池接口动态读取代理，默认接口为 `http://104.234.174.66:7778/api/proxies`；也可以维护手动 HTTP(S) 代理地址。接口须返回 GoProxy 格式的 JSON 数组，尝试可用的 HTTP 节点（暂不使用 SOCKS5），并在整个 UFO 验证码登录过程中固定该代理；代理池不可用时任务失败，不会回退直连。Microsoft 邮箱读取保持直连，注册成功后临时代理不会绑定到账号。随后请求 UFO 验证码，仅从新到的 UFO 相关邮件中提取验证码。成功后将账号加入账号管理，并加载模型和额度；不会改变当前模型目录账号。若原始授权无邮件读取权限、令牌过期、IMAP 不可用或未能识别验证邮件，任务会显示错误，不会伪造注册结果。注册任务状态保存在进程内，重启后未完成任务需重新操作。

现有公网 HTTP 连接会明文传输邮箱刷新令牌；建议先通过 HTTPS 反向代理或本机 SSH 隧道访问控制台，再导入真实邮箱数据。

代理池接口最多 5 个，手动代理最多 100 个；两者至少配置一项。手动代理可包含用户名密码，设置文件位于 `.ufo/settings.json`（Docker 中为 `/data/settings.json`，权限 600）。并发上调后会立即启动排队任务，下调不会中断运行中的任务。代理及邮箱凭据通过公网 HTTP 控制台传输时可能被网络中的第三方读取，建议使用 HTTPS 或 SSH 隧道。

## 控制台界面

控制台采用 Figma 设计的浅色青绿主题，支持桌面列表与手机卡片布局。邮箱导入先进行本地逐行预览校验，确认后才上传；注册前显示所选数量和当前并发。系统设置分为账号调度、注册与代理、访问安全，支持撤销尚未保存的修改。

界面字体为自托管的 Noto Sans SC UI 字符子集（Google Fonts，SIL OFL 1.1），许可证见 `public/fonts/OFL.txt`；其他字符使用系统字体回退。

额度手动刷新以后台任务执行，同一时间只运行一轮，界面显示已完成/总数。采用 16 个并行工作槽，新发起的单账号查询超时为 20 秒；失败项保留已有缓存。浏览器网络请求超时会恢复按钮，再次点击可继续查看仍在执行的任务。普通页面读取额度缓存，不等待上游查询。

### 超长上下文自动摘要

DSH 等客户端的初始指令也可能超过 UFO 单次输入限制。可设置 `UFO_CONTEXT_COMPACT=1` 启用自动摘要（默认关闭）。消息 JSON 超过 16000 字节时，按消息角色分段摘要至总预算 16000 字节；不修改工具调用 ID、参数及消息顺序，最新用户文本在不超过 6000 字节时保留原文。摘要不等同于无损压缩，可能丢失指令细节，并增加延迟和额度消耗。

摘要请求同样受 39000 字节的本地安全上限约束，每次原始请求最多执行 32 次摘要调用。相同账号凭据、工作区、代理、模型、消息角色、文本及预算的摘要在进程内缓存 10 分钟，最多 32 项，不写入磁盘。重启会清空缓存。响应头 `X-UFO-Context-Compacted` 表示被压缩的消息数；最近调用记录中保存压缩耗时和前后字节数，不保存正文。无法压缩的结构数据或过大的工具定义仍会报错；输入超限返回 413，并显示各角色消息的字节数。

Windows PowerShell 启动：`$env:UFO_CONTEXT_COMPACT='1'; npm start`。Docker 用户可在 compose 的 environment 中加入 `UFO_CONTEXT_COMPACT: '1'` 后重新创建容器。

摘要分片最多两个并行；摘要阶段总等待上限 75 秒，超时返回 504 并取消正在进行的摘要请求。已完成分片另有最多 128 项、10 分钟的进程内缓存，中断后重试可复用。阶段进度写入 `.ufo/request-trace.log`，仅包含请求标识、计数、字节数和阶段，不含正文、参数或凭据；超过 1 MiB 后在下一次写入时清空重建。

网页 `parked` 事件会保留暂停原因：工作区额度不足返回 HTTP 402 / `insufficient_quota`，并持久冻结该账号、解除它的全部粘性绑定，避免后续请求继续分配；同一对话下次重试自动改用其他可用账号。重启保留冻结状态，补充额度后手动刷新成功即可恢复；刷新失败或冻结之前发起的旧查询不会解除冻结。其他暂停原因返回 422。适配器会尝试停止已创建的暂停轮次，避免补充额度后旧请求自动继续。

### 网页会话缓存与用量观测

同一对话建议使用固定 `X-Conversation-ID`，不同对话使用不同 ID；未提供时沿用首条用户消息和前置系统指令识别对话。建议保持账号池粘性对话开启，以提高复用率。

缓存仅保存上游会话 ID、消息哈希和过期时间，不落盘；最多 128 个会话，空闲 60 分钟到期，超过 2048 条历史消息不缓存。服务重启后首次请求发送全文。账号额度耗尽切换到其他账号时，首次也会重新发送全文。设置 `UFO_WEB_SESSION_CACHE=0` 可禁用增量模式。

响应头 `X-UFO-Session-Reused` 和 `X-UFO-Input-Bytes` 表示是否复用及本轮发送字节。最近调用 timings 包含 `sessionReused`、`upstreamInputBytes`、`fullInputBytes`，以及上游提供时的 `upstreamTokens`、`upstreamCostMicroUsd`、`upstreamCachePercent`。这些是发送量和上游报告值，不承诺固定收费折扣；最终费用以 UFO 账单为准。

### 工具调用首字延迟

流式请求中，符合 `tool_calls → name → arguments` 顺序的首个工具调用会逐步返回名称和参数，不再等整段长代码生成后才开始输出。参数外层的最后一个右括号、其他工具调用及完成标记，仍等全部响应通过工具名称/JSON Schema 校验后发送；上游失败或校验失败会中断流，不发送 `finish_reason: tool_calls` 或 `[DONE]`。客户端应等待流完整结束后执行工具。混杂说明、未知格式和旧版 `functions` 接口继续使用完整校验后的返回方式。

最近调用的「阶段耗时」分别记录网页助手准备、上游提交、建立响应流、上游首字及客户端首字。上游首字从生成阶段起计时，客户端首字从本地收到请求起计时，实际包含文本或工具数据；不会用空帧或心跳充当首字。此优化降低长工具参数的等待，不改变上游模型本身的排队和推理时间。
