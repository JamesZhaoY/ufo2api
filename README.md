# ufo2api

使用 Node.js 直接连接 UFO，不需要安装 UFO CLI。提供本地可视化控制台、账号切换、账号独立代理和 OpenAI 兼容接口。

## 启动

需要 Node.js 20.18.1 或更新版本：

```sh
git clone https://github.com/JamesZhaoY/ufo2api.git
cd ufo2api
npm install
npm start
```

打开 [http://127.0.0.1:8787/](http://127.0.0.1:8787/) 后，使用首次启动时生成的控制台密码登录；密码保存在 `.ufo/admin-password`（32 位，权限 600）。首次运行会自动导入旧版的登录凭据。要添加账号，点击「添加账号」，输入邮箱，收到验证码后在页面填写。聊天请求由账号池策略选择工作区及出口；已经在运行的请求继续使用发起时的账号。

可为每个账号绑定 `http://host:port` 或 `https://host:port` 代理；如需认证，可以使用 `http://user:password@host:port`。登录、模型查询和对话请求均使用该账号的代理。SOCKS 代理当前不支持。代理地址及登录凭据保存在 `.ufo/accounts.json`，文件权限为 600；界面不显示代理密码或 UFO 凭据。

## Docker 部署

在项目目录中执行：

```sh
docker compose up -d --build
docker compose exec ufo cat /data/admin-password
```

访问 `http://127.0.0.1:8787/`，使用命令输出的 32 位密码登录。Docker 的 `ufo_data` 数据卷保存控制台密码、API Key、账号、代理设置和本地缓存；重新创建容器不会自动更换密码。不要执行 `docker compose down -v`，除非你明确要删除该卷和数据。Docker 使用独立数据卷，不会自动带入本机账号；需要在页面重新登录或导入备份。

默认端口只绑定本机。若要通过 HTTPS 反向代理远程访问，设置 `UFO_PUBLIC_ORIGIN=https://你的域名` 并让代理保留原始 `Host`，然后重新创建容器；浏览器 Cookie 将启用 `Secure`。如果更改 `UFO_HOST_PORT`，也需要将 `UFO_PUBLIC_ORIGIN` 配置为浏览器访问的完整 origin。`UFO_BIND_ADDRESS` 可调整主机绑定地址；直接暴露 HTTP 会使密码和会话在网络中明文传输，应使用 HTTPS 反向代理。

本机直接运行时，可通过 `cat .ufo/admin-password` 查看密码。密码首次生成后保留不变，服务重启会让现有控制台会话失效。控制台密码与 OpenAI API Key 是两个独立凭据。

## OpenAI 兼容接口

- Base URL：`http://127.0.0.1:8787/v1`
- `GET /v1/models`：返回当前账号保存在本地的模型列表，另外包含兼容旧配置的 `ufo` 别名。
- `GET /v1/models/{model}`：查询单个模型，带 `/` 的模型 ID 需要 URL 编码。
- `POST /v1/chat/completions`：`model` 使用返回的模型 ID；`ufo` 和 `auto` 均使用 UFO 自动模型选择。切换模型目录账号后，显示该账号保存的列表。

```sh
curl http://127.0.0.1:8787/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <你的 API Key>' \
  -d '{"model":"gpt-6-luna","messages":[{"role":"user","content":"你好"}]}'
```

`stream: true` 支持 SSE 流式输出。文本消息会拼接传给 UFO 助手，角色隔离和行为不等同于原生 OpenAI API；支持通过提示与结果解析适配函数工具调用和 `json_object`；工具由客户端执行。暂不支持图片、JSON Schema 严格约束、多候选和精确 token 统计，采样参数不会传给 UFO。调用可能消耗 UFO 额度。

默认只监听本机，首次运行会随机生成 API Key，保存在 `.ufo/api-key`（权限 600）。在控制台「系统设置」查看、复制、修改或重新生成；所有 `/v1` 请求都必须携带 `Authorization: Bearer <API Key>`。设置 `UFO_PROXY_API_KEY` 环境变量时，该值优先并锁定页面修改。控制台使用独立的密码登录，不使用 API Key。`UFO_PROXY_HOST`、`UFO_PROXY_PORT`、`UFO_TIMEOUT`（秒）和 `UFO_HOME` 可调整绑定与配置位置。默认只接受本机控制台地址；远程访问需配置 `UFO_PUBLIC_ORIGIN` 和 HTTPS，服务自身不提供 TLS。

UFO 的内部接口并非公开稳定接口，协议变更可能导致模型查询或调用失效。请求关闭 UFO 公共互联网访问，但 UFO 助手仍可能使用工作区工具或请求授权。

测试：`npm test`。

## 批量导入与导出

在「账号管理」点击「导出账号」，可下载全部账号的 JSON 备份；「导入账号」选择同格式的 JSON 文件。备份包含每个账号的邮箱/名称、UFO 登录凭据、工作区地址和代理地址（含代理密码）。**文件是明文，持有者可能访问相应账户；请只在可信设备间传递并妥善保管。**

示例格式：

```json
{
  "format": "ufo-accounts",
  "version": 1,
  "accounts": [
    {"name": "user@example.com", "token": "UFO 登录凭据", "workspace": "https://app.ufo.ai", "proxy": "http://127.0.0.1:7890"}
  ]
}
```

导入最多 500 个账号、文件不超过 2 MB。按不区分大小写的账号名称与工作区地址匹配：已有账号会跳过，不覆盖凭据或代理；其余账号合并添加。整个文件必须通过格式校验才会保存，导入不会改变已有当前账号。只有账号列表为空时，第一个导入的账号会成为当前账号。导入后会尝试一次加载模型和额度；凭据过期时需要重新登录。导入来源不可信的文件可能将请求和账号凭据发送到文件中指定的工作区或代理，请只导入可信备份。

## 账号池、额度与粘性对话

控制台的「系统设置」提供三种策略：

- **优先额度**：在已知余额且未到拒绝阈值的账号中，选择 `余额 − UFO 拒绝阈值` 最大的账号；无已知可用余额时才使用额度未知的账号。
- **随机负载**：从未确认耗尽的账号中随机选择。
- **轮询使用**：依次选择未确认耗尽的账号。默认策略为轮询。

账号余额来自 UFO 的工作区账单接口，显示的是余额及扣除拒绝阈值后的可用金额，不是 token 数。UFO 未设置支出限制时，不能据此认定额度无限；查询失败显示为未知，而非零。额度保存在本地，不因时间到期或普通调用而自动刷新；页面的「刷新额度」手动重新查询。登录、导入或首次迁移现有账号时会加载一次。额度已达拒绝阈值的账号不会分配新请求。未知额度的账号仍可能被选择，但上游若拒绝请求，接口会返回错误，不会自动重试以免重复执行。

「模型目录账号」切换只控制页面和 `/v1/models` 显示的账号，聊天请求由账号池分配。指定模型时，仅在能够确认支持该模型的账号中选择。

粘性对话默认开启，有效期默认 60 分钟。推荐客户端对同一对话发送相同的 `X-Conversation-ID` 请求头；不同对话使用不同 ID。未提供时，系统根据开头的 system/developer 消息和首条 user 消息识别对话，因此相同开头的不同对话可能被识别为同一会话。粘性映射保存在进程内，超时或服务重启会清除；绑定账号不再可用时返回错误，不自动切换账号。代理每次仍向 UFO 创建新会话并传入客户端提供的完整消息历史：固定账号可能有助于上游缓存，但缓存是否命中由 UFO 决定，本服务未验证缓存命中率，也不会代替客户端保存对话历史。

## 首页与最近调用

「首页概览」显示账号数量、已知可用总额度及最近调用状态。总额度按凭据中的工作区标识去重，并扣除 UFO 的拒绝阈值；无法查询、未设置支出限制或缺少额度数据的账号不会计入，页面会提示。若无法识别工作区，合计可能重复。

从本版本开始，服务最多在 `.ufo/activity.json` 保留最近 200 次聊天接口请求的时间、账号 ID、账号名称、模型、结果、HTTP 状态和耗时，权限为 600。不会保存请求或回复内容、验证码、会话 ID、密钥或代理地址；升级前的请求不会回填。页面的调用统计和列表仅基于这些本地记录，不代表 UFO 全部历史用量。用户中断的流式请求会标记为中断，服务端返回错误会标记失败。

## 工具调用兼容范围

支持 OpenAI Chat Completions 的 `tools`、`tool_choice`、`tool_calls`、`role: tool` 和旧版 `functions`/`function_call`，以及 `response_format: {"type":"json_object"}`。代理将工具定义和历史交给 UFO，并将其文本结果解析为标准 `tool_calls`；工具实际由客户端执行并提交结果。工具调用需等筛选与校验完成；单页筛选若按预期先确认无需工具，可提前流式输出文本，其他情况会回退到缓冲输出。普通文本流仍实时输出。上游不保证严格遵守函数 JSON Schema，也可能返回无法解析的内容；此时会返回错误，不会执行工具或伪造结果。JSON Schema 结构化输出和多模态工具暂不支持。


DSH 等客户端提供大量工具时，代理会按 UFO 的单次输入大小限制分页发送工具名称，不在初选阶段发送无关工具的说明。它会在预算允许时提供与请求相关的少量完整定义，让模型在一次调用中选择工具并生成参数；参数通过 JSON Schema 校验才直接使用，否则回退到再次生成。最多选 8 个工具参与本轮调用。工具选择基于模型判断，不能保证一定选中正确工具，且分页可能增加延迟与用量。如果单独的对话历史已超过上游可接收的长度，代理会报错，需要缩短上下文。UFO 模型拒绝请求时，代理返回 422，避免客户端对拒绝结果反复重试。

最近调用记录还显示账号检查、工具筛选、上游生成和首字输出的耗时（旧记录没有这些分项）。模型和额度保存在 `.ufo/state-cache.json`（权限 600），正常聊天请求以及进程重启均使用本地数据；登录、导入或首次迁移旧账号时会加载一次，之后只能手动刷新。实际余额可能已经改变，额度优先策略也基于上次保存的值；如遇余额不足、账号变更或模型列表变化，请手动刷新。大工具目录的快路径在条件允许且参数通过校验时可省去一次生成；否则回退到原两阶段流程。
